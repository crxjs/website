  ::div{label="Firefox" icon="logos:firefox"}
    ::steps
      ### Configure a Firefox build
      In `vite.config.ts`, set the CRXJS plugin option `browser: 'firefox'` as shown in the [browser-support example](/guide/introduction#browser-support). Check your extension manifest for Firefox-specific requirements.

      ### Build the extension
      :pm-run{script="build"}

      ### Open Firefox debugging
      In Firefox, open `about:debugging` and select **This Firefox**.

      ### Load Temporary Add-on
      Select **Load Temporary Add-on**, then choose `manifest.json` in the generated `dist` directory (or your configured output directory). Firefox will load the extension temporarily.

      ### Inspect or reload
      Use **Inspect** to debug the extension, or **Reload** after rebuilding. Temporary add-ons are removed when Firefox restarts.

      For limitations of temporary installation, see [Mozilla's Firefox Extension Workshop](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/). This workflow describes testing a Firefox build; it is not a claim that the Chrome/Edge development-server behavior is identical in Firefox.

## Developing the popup

An extension popup normally closes when it loses focus. To keep it open while
editing, right-click the extension's toolbar icon and select **Inspect popup**.
The popup stays open while its DevTools window is attached.

Without a framework-specific HMR handler, changes to the popup's HTML or
JavaScript reload the extension page. Imported CSS can update in place without a
full reload, which lets the current page state remain intact. Framework plugins
such as React or Vue can provide more granular component updates.
